# 法师花 · MageBloom

> 魔兽世界：无限（WoW Forever，客户端 1.60.1 / Interface 16001）法师专用智能循环。
> **设计先行、决策可复现、数值有出处、每次改动可验证。**

本项目不是又一个"抄一份 APL 的壳"。它要解决的是小六月（LiuyueForever）这类一键插件在**法师**上的四个结构性问题：

1. 内置法师 APL 只有 3–4 条，触发、层数、法力、AOE、移动全部缺失；
2. 规则引擎没有"buff 存在且层数 ≥ N""debuff 剩余时间 < X"这类条件，写不出真正的循环；
3. 决策不可观测：选了什么、为什么选、跳过了谁，玩家和开发者都看不到；
4. 没有回归体系：改一条规则，无法证明它比原来好。

## 五条设计原则

1. **观测 / 决策 / 执行三层分离。** 决策是纯函数：同一状态快照必然得到同一建议，可在测试里复现。
2. **每个数字有出处。** 技能 ID、触发 ID、优先级来源、客户端构建号，全部写进数据字典；禁止"凭感觉"的魔法数。
3. **先测量，再调参。** 任何规则改动都要有指标（触发利用率、断条率、与模拟器的决策一致率、木桩 DPS 比）。
4. **失败要保守。** 状态读不到、技能未学会、距离不够、正在引导——一律不推荐，绝不猜。
5. **只响应玩家按键。** 插件不自动施法、不自动移动、不自动选目标；一次按键 = 一次动作。

## 设计上明确继承小六月的部分

- 安全派发通道（tooltip 宽度编码 + `SecureHandlerWrapScript`）——这是它最聪明的设计，保留并工程化；
- 一键按钮 + 专精自动识别 + 脱战重编译，不要求 `/reload`；
- "策略与外壳分离"的思路：策略是数据，外壳负责状态与派发；
- APL 字符串导入/导出的玩家生态。

明确替换的部分：法师 APL、条件引擎、可观测性、测试体系、字符串混淆（改为可审阅源码）。
