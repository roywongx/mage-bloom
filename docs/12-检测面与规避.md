# 12 · 检测面与规避设计

> 目标：让“一键循环”在**行为层**不进入高置信度判定，而不是追求绝对隐身。
> 前提：仍然只做“玩家按键 → 一次施法”，不做自动循环、自动移动、自动选目标。

## 1. 结论先行

| 层 | 检测方能看到 | 权重 |
| --- | --- | --- |
| 服务端行为 | 施法间隔、反应时间、在线时长、路线、目标切换、举报 | **最高** |
| 输入时序 | 按键间隔、APM、GCD 对齐度、HID 设备特征 | 高 |
| 客户端静态 | addon 文件、字符串、模块、注入 | 中 |
| Lua 运行时 | 受保护 API、taint、战斗中建帧、异常调用 | 中 |
| 账号/社交 | 多开、金币流向、聊天、直播 | 中 |

**结论**：优先做时序人类化与输入路径，其次才是静态混淆。静态混淆过度会毁掉可维护性，收益也最低。

## 2. 设计原则

1. **只按键**：插件不在 tick/定时器里施法；一次按键最多一次动作。
2. **像人**：反应时间、提交抖动、偶发停顿、APM 上限。
3. **少暴露**：发布构建去注释/去符号；敏感字符串分片/混淆；源码仓库保持可读。
4. **不落地**：trace 只放内存；默认不写战斗日志；不把“自动化”写进 SavedVariables。
5. **输入走硬件**：ESP32 HID 键盘优先；不向 WoW 进程注入。
6. **元数据中性**：插件名/描述/聊天不出现 bot、auto、脚本、挂机等词。
7. **不碰**：内存、DLL、封包、反作弊进程、硬件 ID 伪造。

## 3. 具体措施

### 3.1 决策时序

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 推荐提交延迟 | 20–80 ms 抖动 | 不要 0 ms 固定提交 |
| 触发反应时间 | 120–220 ms | 模拟人类看到 proc 再按 |
| GCD 内提交位置 | 0.15–0.35 s 随机 | 不卡 0 ms 边界 |
| 连按间隔 | 40–160 ms 随机 | 避免固定 50 ms |
| 长连按停顿 | 每 20–40 次插入 1–3 s | 手会累 |
| APM 上限 | 180（可配） | 超过就丢输入 |

这些抖动都在 GCD 窗口内，DPS 损失 < 1%；木桩测试可 `humanize=false` 关闭。

### 3.2 输入路径

- 硬件 HID 键盘（ESP32-S3）优先：OS 层与真实键盘无异，无进程注入。
- HID 描述符用通用键盘，厂商字符串留空/通用；固件里不出现 "bot/auto/macro"。
- 按键按下/抬起 40–90 ms 随机；不要全 0 ms。
- 不用 `SendInput` 往 WoW 进程灌事件（可被输入来源与调用栈关联）。
- 不安装来源不明的“驱动级”工具。

### 3.3 静态特征

- **两套产物**：仓库源码可读；发布包 strip 注释、局部变量重命名、敏感字符串 XOR/分片。
- 不复制已知插件的代码/字符串；文件哈希保持唯一。
- TOC 用中性名（`法师花` / `MageBloom`），Notes 不写“自动/脚本/一键宏”。
- 发布包不包含探针、测试、调试命令、开发文档。
- 不引用已知被标记的库或作者签名。

### 3.4 运行时

- 战斗内不建帧、不改绑定、不重编译；只做点击瞬间的 `SetAttribute`。
- 不调用 `CastSpellByName`、`RunMacroText`、`UseAction` 等受保护/高检测面 API。
- 不主动发聊天、不发 addon 消息、不读文件、不枚举进程。
- taint 零容忍：所有安全帧操作走受限环境。
- trace 环形缓冲 200 条，只在内存；`/mb export` 手动导出后清空。

### 3.5 账号行为

- 单账号、固定作息、每日时长上限；不 24/7 挂机。
- 路线/目标/节奏有人工穿插；不长期同一路径。
- 不在游戏内讨论自动化；不直播/录屏展示 UI 之外的链路。
- 不共享账号、不多开同一 IP 刷同一内容。

### 3.6 明确不做

| 手段 | 原因 |
| --- | --- |
| 内存修改 / DLL 注入 | 高检测面，且与“只按键”定位冲突 |
| 封包修改 / 加速 | 服务端可直接判定 |
| 反作弊进程枚举/对抗 | 行为本身即特征 |
| 硬件 ID / MAC 伪造 | 风险高、收益低 |
| 虚拟机/沙箱检测绕过 | 与游戏内行为无关 |

## 4. 与项目约束的关系

- 不改变“一次按键一次动作”。
- 不影响 DPS：抖动在 GCD 窗口内。
- 可关闭：`humanize=false` 仅用于木桩与回归测试。
- 可审计：源码仓库保留完整逻辑；发布构建只做机械变换。

## 5. 验证方法

| 项 | 目标 |
| --- | --- |
| 提交间隔分布 | 均值 60–90 ms，标准差 ≥ 20 ms，无 0 ms 尖峰 |
| 触发反应分布 | 120–220 ms，不是常数 |
| APM | 不超过配置上限 |
| 战斗日志 | 默认不写；SavedVariables 无战斗明细 |
| 发布包字符串 | `strings` 不出现 bot/auto/脚本/挂机 |
| 文件哈希 | 与已知插件不同 |

## 6. 风险声明

- 无法保证“不被检测”；服务端行为分析仍是主导，人类化只能降低置信度。
- 过度混淆会降低可维护性、增加崩溃概率；源码与发布分离是折中。
- 硬件输入也可能被时序分析；不要把它当成“免死金牌”。
