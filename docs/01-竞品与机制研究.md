# 01 · 竞品与机制研究

研究时间：2026-11-20。客户端：`1.60.1.70959`（ForeverDB 2026-11-18 数据）。所有外部结论附链接；ID 的置信度见 [09 数据字典](09-法师数据字典.md)。

## 1. 生态地图

| 方案 | 载体 | 目标版本 | 策略来源 | 优点 | 局限 |
| --- | --- | --- | --- | --- | --- |
| **虚空之花** | WeakAuras 字符串 | 泰坦重铸 3.80.x | 哀冬、春夏秋 + 社区二创 | 策略多（24–43 套）、更新快、生态大 | 与 WA 强绑定；字符串不可审阅；**不是无限服** |
| **BD-PVE** | 独立插件壳 | 泰坦重铸 3.80.2 | 搬运虚空之花策略 | 免 WA、切天赋不重载、偷药/炸弹兜底 | 只支持 3.80；与虚空之花互斥 |
| **小六月 LiuyueForever** | 独立插件 | **无限 1.60.1** | 自研 APL + AI 问答 | 安全派发成熟、一键交互完整、支持自定义 APL 字符串 | 法师 APL 极薄；条件集不足；混淆；无测试/观测 |
| **Hekili** | 独立插件 | 正式服（已停止） | SimulationCraft APL | **多步预测**、队列显示、APL 可编辑 | 无无限服版本；正式服 12.0 已终止 |
| **WowSims Forever** | 模拟器 + APL JSON | **无限 1.60.1** | 社区理论组 | 权威、可复现、带 commit | 只是模拟器，不是游戏内插件 |
| **ForeverDB** | 数据库/指南 | 无限 1.60.1 | 模拟器跑分 + 日志 | 阈值与占比有数据 | 描述性，不是执行器 |
| **Eternadex** | 数据库/指南 | 无限 1.60.1 | 客户端数据 | 机制描述清楚 | 非执行器 |
| **SpellActivationOverlay** | 独立插件 | 多版本含 Forever | 社区 | 触发 ID 完整、Forever 分支 | 只做提示，不做循环 |

**结论**：无限服没有"现成的、可审阅的、带测试的"法师循环执行器。小六月占了位置但没做深；虚空之花系是另一个版本。我们的空位是**无限服 + 法师 + 工程化**。

## 2. 各方案拆解

### 2.1 虚空之花（WA 字符串）

- 形态：WeakAuras 自定义 Lua，字符串内嵌状态机与施法建议。
- 分发：网易 DD 字符串库；社区二创在文件头署名。
- 生态位：泰坦重铸（3.80.x）的事实标准；BD-PVE 等外壳把"策略"与"派发"拆开。
- 可借鉴：**策略与外壳分离**、按专精组织、社区可二创。
- 不可直接复用：版本不同（3.80 vs 1.60），技能表与触发完全不同。

来源：
- NGA《TitanTimeCombat 虚空之花插件版》<https://bbs.nga.cn/read.php?tid=47694558>
- 新手盒子 BD-PVE 页面 <https://www.wclbox.com/games/1/PluginItem/32327>

### 2.2 BD-PVE（外壳）

- 自述："输出策略的源头是虚空之花……本插件只是把这些策略跑起来的执行外壳"。
- 派发机制"参考过潘少的开源实现"。
- 明确与虚空之花互斥（会抢按键）。
- 可借鉴：**外壳只做状态 + 派发**、偷药/炸弹兜底、切专精不重载。
- 不可复用：3.80.x 专用。

### 2.3 小六月 1.3.4（本次迭代对象）

- 42 个 Lua、19 MB（含 831 个语音 ogg）、Interface 16001。
- 字符串全量 XOR(123) 混淆，代码逻辑明文。
- 核心：`Engine/Smart.lua`（安全派发）、`Core/APL.lua`（320 KB 规则与解析）、`AI/LiuyueAI.lua`（301 KB 问答）。
- 优点：安全信道、一键交互、专精自动切换、APL 字符串导入。
- 缺陷：法师规则少、条件集不足、无 trace、无测试。详见 [08](08-小六月原版分析.md)。

### 2.4 Hekili（方法论）

- 核心不是"优先级列表"，而是**按 APL 向前模拟若干步**，显示接下来 3–5 个动作。
- 玩家偏离建议时立即重算。
- 正式服因 12.0 API 变化终止（2026-01-20），但其"多步预测 + 队列"是我们要移植的思想。
- 可借鉴：**预测窗口**、**队列显示**、**可编辑 APL**。

来源：<https://github.com/Hekili/hekili>

### 2.5 WowSims Forever（权威 APL）

仓库：`wowsims/forever`，法师 APL 位于 `ui/specs/mage/dps/apls/`：

| 文件 | 方案 | 用途 |
| --- | --- | --- |
| `frost.apl.json` | 深冰 | 寒冰箭填充 + 寒冰指冰枪 + AOE 组 |
| `deepFire.apl.json` | 深火 | 灼烧维持 + 热力迸发炎爆 + 火球 |
| `ffb.apl.json` | 霜火 | 灼烧 + 热力迸发 + 霜火之箭 |
| `arcane.apl.json` | 奥术 | 飞弹连射飞弹 + 奥术愤怒 + 奥冲 |
| `arcaneFireFill.json` | 奥火混合 | 热力迸发炎爆 + 奥冲层数管理 |

我们以这些 JSON 为**语义基线**（不是照抄代码），并把 commit 固定进 profile 元数据。

### 2.6 ForeverDB（校准数据）

- 构建 `1.60.1.70959`。
- 关键阈值：唤醒 < 15% 法力；奥术冲击在 < 25% 法力时仍作为泄蓝；节能施法 15 秒窗口；飞弹连射 15 秒窗口。
- 输出占比（60 级、180 秒）：奥术飞弹 ~55%、奥冲 ~35%、魔杖 ~10%；火焰火球 ~44%、火冲 ~25%、灼烧 ~14%；冰霜寒冰箭 ~67%、火冲 ~16%、冰枪 ~10%。
- 这些占比是我们 A/B 的对照目标。

来源：<https://foreverdb.net/class/Mage/pve>

### 2.7 Eternadex（机制说明）

- 冰枪术对冻结目标 **300%** 伤害；寒冰指使目标视为冻结；深冬之寒只提升**自己**的冰枪/寒冰箭暴击；强化灼烧只作用于**自己**的火焰伤害。
- 冰法 PvE 加点 32/19，冰枪、寒冰指、碎冰、寒冰护体。
- 火法：热力迸发让炎爆变快；燃烧提高暴击；移动用火焰冲击；AOE 烈焰风暴/冲击波。
- 奥法：奥冲叠加智力转法伤，飞弹连射强化飞弹，奥术强化 + 气定神闲爆发。

来源：
- <https://eternadex.com/zh/klassen/magier/frost/>
- <https://eternadex.com/zh/klassen/magier/feuer/>
- <https://eternadex.com/zh/klassen/magier/arkan/>

### 2.8 SpellActivationOverlay（触发 ID）

SAO 的 `classes/mage.lua` 对 Forever 分支有专门处理，给出：

- `400625` 热力迸发（1/2/3 层）
- `400670` 寒冰指（1–2 层）
- `400589` 飞弹连射
- Forever 关闭了标准 Frozen 检测，改用 `5276` 作为"冻结"提示锚点

这些 ID 与 WowSims 的 `400669`（寒冰指）存在**候选差异**，因此我们的状态层同时接受 `400669/400670`（见数据字典的候选策略）。

## 3. 无限服法师机制（当前认知）

### 3.1 三系定位

| 专精 | 核心资源 | 主要输出 | 爆发 | 关键触发 |
| --- | --- | --- | --- | --- |
| 冰霜 | 法力 | 寒冰箭、冰枪术 | 急速冷却（重置冰环/护体） | 寒冰指、冻结、深冬之寒 |
| 火焰 | 法力 | 火球术、灼烧、火焰冲击 | 燃烧 | 热力迸发（3 层） |
| 奥术 | 法力 | 奥术冲击、奥术飞弹、奥术愤怒 | 奥术强化 + 气定神闲 | 飞弹连射、节能施法 |

### 3.2 WowSims 条件语义（节选）

**冰霜（frost.apl.json）**
1. 法力 ≤ 5% → 阅读魔网 + 唤醒（引导到 99% 打断）
2. 寒冰指（400669）激活 → 交其他冷却
3. 目标 ≥ 3 → AOE 组：寒冰指 ≥1 → 冰锥术；寒冰指 ≥1 → 冰枪术；冰锥 CD ≥5 → 急速冷却；无寒冰护体 → 寒冰护体；否则暴风雪
4. 冰锥 CD ≥7 → 急速冷却
5. 目标深冬之寒（12579）层数 = 5 → 冰锥术
6. 寒冰指层数 =1 且正在施放寒冰箭 → 冰枪术
7. 寒冰护体剩余 ≤3 秒 → 寒冰护体
8. 寒冰箭

**火焰（deepFire.apl.json）**
1. 法力 < 炎爆术消耗 → 唤醒
2. 热力迸发层数 = 3 且不在施放炎爆 → 炎爆术
3. 火焰冲击
4. 目标火焰易伤（22959）层数 <5 或剩余 <5 → 灼烧
5. 奥术冲击增益（400573）缺失或剩余 <1.5 秒 → 奥术冲击
6. 飞弹连射（400589）→ 奥术飞弹
7. 火焰冲击 CD ≥ 火球读条 → 火球术
8. 灼烧填充

**奥术（arcane.apl.json / arcaneFireFill.json）**
1. 法力 ≤10% → 唤醒
2. 飞弹连射或奥术愤怒就绪 → 交冷却
3. 飞弹连射 → 奥术飞弹
4. 奥术愤怒就绪 → 气定神闲 + 奥术愤怒
5. 奥术愤怒
6. 火焰冲击
7. 奥术冲击

## 4. 方案对比结论

| 维度 | 虚空之花 | BD-PVE | 小六月 | 本项目 |
| --- | --- | --- | --- | --- |
| 无限服 | ✗ | ✗ | ✓ | ✓ |
| 法师深度 | 中（3.80） | 中 | 低 | **高** |
| 触发/层数条件 | 有（WA Lua） | 有 | 无 | **有** |
| 可审阅 | ✗ | ✗ | ✗ | **✓** |
| 可测试 | ✗ | ✗ | ✗ | **✓** |
| 多步预测 | 部分 | 部分 | 无 | **M2 引入** |
| 一键派发 | WA | ✓ | ✓ | ✓（继承并工程化） |

**采用策略**：以 WowSims 的 APL 语义为骨架，叠加 ForeverDB 的阈值与 Eternadex 的机制说明，做成**数据驱动的 profile**；执行层继承小六月的安全信道；观测层与测试层从零建立。
