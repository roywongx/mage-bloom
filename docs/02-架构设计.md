# 02 · 架构设计

## 1. 总览

```
┌──────────────────────────────────────────────────────────────┐
│                        UI / 配置 / 遥测                        │
│   按钮皮肤 · 队列预览 · 触发条 · /mb 面板 · trace 导出          │
└───────────────▲──────────────────────────────▲───────────────┘
                │ Decision + Trace             │ Config
┌───────────────┴──────────────────────────────┴───────────────┐
│                         Decide（纯函数）                       │
│  Profile → Guards → Priority → (可选) Lookahead → Decision     │
│  不调用任何写 API；无全局副作用；可离线复现                       │
└───────────────▲──────────────────────────────┬───────────────┘
                │ State                        │ Decision
┌───────────────┴──────────────┐   ┌───────────▼───────────────┐
│      Observe（只读快照）       │   │   Act（安全派发）          │
│ 光环 · 冷却 · 资源 · 施法状态  │   │ 索引 → 宽度 → wrap script │
│ 姓名板 · 移动 · 目标 · GCD    │   │ 点击瞬间改属性 → 施法       │
└───────────────▲──────────────┘   └───────────▲───────────────┘
                │                              │
        ┌───────┴────────┐             ┌───────┴────────┐
        │  WoW Client API │             │  Secure Frame   │
        └────────────────┘             └────────────────┘
```

三条硬边界：

1. **Observe 不写**：只调用只读 API，不 SetAttribute、不 CastSpell。
2. **Decide 不碰游戏**：输入状态与配置，输出决策；测试里可用假状态跑一万次。
3. **Act 不思考**：只执行 Decide 已提交的索引；点击瞬间在受限环境完成属性设置。

## 2. 运行时模式

### 2.1 Companion 模式（M1，默认）

- 依赖 `LiuyueForever`，不修改其文件。
- 运行时替换 `LF.APL.EffectiveChain` / `LF.APL.PickIndex`（仅当玩家是法师且本插件启用）。
- 复用其安全按钮、专精识别、日志、按键绑定。
- 优点：一周内可用；风险低；可直接对比原版。
- 缺点：受上游版本影响；两套配置并存。

### 2.2 Standalone 模式（M3）

- 自带 Observe/Decide/Act/UI，不再依赖小六月。
- 复用同一套 `core/` 模块；Companion 只是适配器。
- 迁移条件：核心测试与游戏内 A/B 达标，且安全信道在至少 3 个客户端构建上稳定。

### 2.3 适配层

```
adapter/
  liuyue.lua     -- 注入/卸载 hook，版本探测
  standalone.lua -- 自建按钮与事件
```

上游版本号写入日志；不认识的版本默认只读（不接管），避免破坏。

## 3. 模块划分

| 模块 | 文件 | 职责 | 依赖 | 预算 |
| --- | --- | --- | --- | --- |
| 启动/配置 | `Core.lua` | DB、事件、命令、模式切换 | — | 一次性 |
| 状态 | `State.lua` | 快照、光环扫描、冷却、施法/引导、姓名板 | API shim | ≤0.25 ms/次 |
| 规则数据 | `profiles/mage/*.lua` | 三系 profile + 元数据 | — | 载入时校验 |
| 决策 | `Engine.lua` | 条件求值、优先级、队列、trace | State, Profile | ≤0.05 ms/次 |
| 派发 | `Act.lua` | 宽度编码、wrap snippet、失效检测 | Secure API | 点击时 |
| 展示 | `UI.lua` | 按钮、队列、触发条、面板 | Engine | ≤0.1 ms/帧 |
| 遥测 | `Trace.lua` | 环形缓冲、导出、回放 | — | 采样 |
| 兼容 | `adapter/*.lua` | 小六月 / 独立 | — | — |

## 4. 状态模型

`State` 是不可变快照（每次 tick 重建），字段如下：

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `t` | number | `GetTime()` | 快照时间 |
| `inCombat` | bool | `UnitAffectingCombat` | |
| `dead` | bool | `UnitIsDeadOrGhost` | |
| `moving` | bool | `IsMoving` | 读不到时 `nil` |
| `mana`, `manaMax`, `manaPct` | number | `UnitPower(0)` | |
| `hpPct` | number | `UnitHealth` | |
| `target` | table? | `UnitExists/CanAttack` | `{exists, hostile, hpPct, casting, interruptible, distance}` |
| `buffs` | map | 光环扫描 | `byId[id]`, `byName[name]` → `Aura` |
| `debuffs` | map | 光环扫描（target） | 同上 |
| `cast` | table? | `UnitCastingInfo` | `{name, spellID, remain, notInterruptible}` |
| `channel` | table? | `UnitChannelInfo` | 同上 |
| `aoe` | number | `C_NamePlate` | 敌对且存活姓名板数 |
| `gcd` | number | 冷却推断 | 剩余 GCD（秒） |
| `spec` | string | 天赋 | `FIRE/FROST/ARCANE` |
| `spellCD` | map | `C_Spell.GetSpellCooldown` | 按需缓存 |

`Aura` 结构：

```lua
{
  id = 400625, name = "热力迸发",
  stacks = 3,          -- applications
  remain = 12.4,       -- expirationTime - now（nil = 永久/未知）
  duration = 20,
  source = "player",   -- 仅记录，不参与决策（除非规则要求）
}
```

**扫描策略**：每个 tick 扫描玩家增益（≤40）与目标减益（≤40），建立 `byId` / `byName` 两张表；规则查询 O(1)。扫描失败（API 变更）时降级为按需 `FindAura`，并在 trace 标记 `degraded=true`。

## 5. 决策模型

```lua
-- 纯函数；无全局写入
function Decide(state, profile, config) -> Decision

Decision = {
  index = 3,              -- profile.rules 下标
  ruleId = "frost.ice_lance.fof",
  spellID = 1240047,
  spellName = "冰枪术",
  trace = { {rule="frost.barrier", ok=false, why="buff 1326891 存在"}, ... },
  committedAt = 12345.6,
}
```

求值规则：

1. 规则按 profile 顺序；第一条全部 guard 通过者胜出。
2. guard 为 `all` 语义；任一失败即跳过，并记录原因。
3. 全局 guard 先行：死亡、坐骑、目标无效、配置禁用 → 直接无推荐。
4. 技能可用性 guard：未学会、法力不足、距离不符、正在引导且候选需读条 → 跳过。
5. 结果确定：同一 `(state, profile, config)` 必得同一 `Decision`。

### 5.1 预测（M2）

可选 `lookahead=2`：对候选动作做**轻量投影**（不跑完整模拟）：

- 资源：扣蓝、回蓝（五秒规则不建模，只按技能消耗）；
- 层数：奥冲 +1、炎爆清零热力迸发、冰枪消耗 1 层寒冰指；
- 冷却：按已知 CD 推进；
- 评分：`Σ damage_weight × proc_multiplier - mana_penalty`。

预测只用于**队列展示**与同分排序，不改变首条命中语义；默认关闭，避免"聪明反被聪明误"。

## 6. 执行模型

详见 [04 安全派发通道](04-安全派发通道.md)。要点：

- 决策索引 `1..N` 编码为 tooltip 左内边距宽度（步长 8 px）；
- 两个隐藏 tooltip 同时写入，点击前在受限环境比较宽度一致才提交；
- `SecureHandlerWrapScript(button, "OnClick", button, snippet)` 在点击瞬间设置 `type/spell/unit`；
- 战斗中不修改属性、不重建按钮；脱战才允许重编译。

## 7. 事件与节流

| 事件 | 动作 |
| --- | --- |
| `PLAYER_LOGIN` / `ADDON_LOADED` | 建库、探测适配器、首次编译 |
| `PLAYER_ENTERING_WORLD` | 重建状态、重新编译（脱战） |
| `PLAYER_TALENT_UPDATE` / `CHARACTER_POINTS_CHANGED` | 切 profile、标记待编译 |
| `UNIT_SPELLCAST_SUCCEEDED/FAILED` | 更新本地冷却账本、触发一次即时重算 |
| `PLAYER_REGEN_ENABLED` | 执行挂起的重编译 |
| `OnUpdate` | 10 Hz 快照 + 决策（非战斗 2 Hz） |

战斗中禁止：建帧、改安全属性、`SetBinding`、重编译。所有此类请求排队到脱战。

## 8. 性能预算

| 项 | 目标 | 测量 |
| --- | --- | --- |
| 快照（40+40 光环） | ≤ 0.25 ms | 微基准 10k 次 |
| 决策（≤16 规则） | ≤ 0.05 ms | 微基准 100k 次 |
| UI 更新 | ≤ 0.1 ms/帧 | 帧耗时对比 |
| 内存 | ≤ 2 MB（不含字体/材质） | `/mb mem` |
| GC | 热路径零表分配 | 代码审查 + 分配计数 |

## 9. 失败与降级

| 失败 | 检测 | 降级 |
| --- | --- | --- |
| 光环 API 变更 | `C_UnitAuras` 不存在/报错 | 走 `UnitAura` 旧接口；trace 标记 |
| 冷却 API 变更 | `C_Spell.GetSpellCooldown` 报错 | 走 `GetSpellCooldown`；再失败用本地账本 |
| 宽度信道失效 | 标定宽度重复/不可读 | 关闭动态派发，仅脱战设技能；提示用户 |
| 上游小六月改版 | 版本号/函数签名不匹配 | 进入只读模式，不接管 |
| 决策异常 | pcall 包裹 | 返回无推荐，记录 trace，不施法 |

## 10. 数据与校验

- 每个 profile 带 `meta`：`game_build`、`source`（URL + commit）、`updated_at`、`authors`。
- 载入时校验：技能可解析、ID 唯一、规则引用存在、无未知字段（严格模式仅告警）。
- CI 中跑 schema 校验与离线 fixture；不通过不允许合并。
