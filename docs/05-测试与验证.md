# 05 · 测试与验证

> 原则：**能在离线证明的，不在游戏里猜；必须在游戏里验证的，写成可复现实验。**

## 1. 测试金字塔

```
        ┌────────────────────┐
        │ 游戏内 A/B（周级）   │  木桩日志、DPS、触发利用率
        ├────────────────────┤
        │ 集成（Mock 客户端）  │  事件序列、战斗锁定、重编译
        ├────────────────────┤
        │ Parity（对比模拟器） │  WowSims APL → IR，状态语料对比
        ├────────────────────┤
        │ 属性测试（Property） │  不变量：永不返回非法技能
        ├────────────────────┤
        │ 单元测试（Golden）   │  单条规则/单条件
        └────────────────────┘
```

## 2. 离线测试环境

### 2.1 Mock WoW API

`tests/mock.lua` 提供最小可运行环境：

- `UnitAura / C_UnitAuras.GetAuraDataByIndex`：从 fixture 注入光环；
- `UnitCastingInfo / UnitChannelInfo`：注入读条/引导；
- `C_Spell.GetSpellCooldown`：注入冷却表；
- `UnitPower / UnitHealth / UnitExists / UnitCanAttack`；
- `C_NamePlate.GetNamePlates`：注入 N 个姓名板；
- `GetTime`：可控时钟（推进 0.1s）；
- `SecureHandlerWrapScript`、`CreateFrame`：记录调用，不执行真实逻辑。

Fixture 格式（JSON，便于审阅与生成）：

```json
{
  "name": "frost_fof_1stack",
  "spec": "FROST",
  "time": 100.0,
  "player": { "manaPct": 80, "hpPct": 100, "moving": false },
  "target": { "exists": true, "hostile": true, "hpPct": 100 },
  "buffs": [ { "id": 400669, "stacks": 1, "remain": 10 } ],
  "debuffs": [],
  "cooldowns": { "1240047": 0 },
  "aoe": 1,
  "expect": { "spell": "冰枪术" }
}
```

### 2.2 单元 / Golden

- 每条规则至少 2 个 fixture：命中、不命中（含失败原因）。
- 每个 profile 至少 1 个"完整循环"fixture：连续 10 个 tick，断言输出序列。
- Golden 文件与 profile 同版本；profile 改动必须更新 golden 并在 changelog 说明。

### 2.3 属性测试（不变量）

对随机状态生成器跑 10,000 次，断言：

1. 返回的 `index` 要么 `nil`，要么在 `1..#rules`；
2. 返回的技能必须在 profile 中声明；
3. 玩家死亡、目标不存在、配置关闭时返回 `nil`；
4. 正在引导时，返回的技能必须是瞬发（或 `nil`）；
5. 同一状态两次调用结果相同（纯函数）；
6. `trace` 中每条被跳过规则必须有 `why`。

## 3. Parity：与 WowSims APL 对比

### 3.1 目标

不是"逐字复刻模拟器"，而是证明**在模拟器覆盖的状态空间里，我们的决策一致率足够高**；差异必须能被解释（例如我们更保守地避免断引导）。

### 3.2 方法

1. `tools/apl_import.lua` 把 `ui/specs/mage/dps/apls/*.apl.json` 转成 IR；
2. 生成状态语料：组合资源（法力 0/10/25/50/100%）、触发（无/1/2/3 层）、冷却（就绪/剩余）、目标数（1/3/5）、移动（是/否）、施法（无/读条/引导）；
3. 两侧各自求值，比较"首选技能"；
4. 输出混淆矩阵与差异清单（按规则聚合）。

### 3.3 指标

| 指标 | 目标 |
| --- | --- |
| 首选一致率 | ≥ 90% |
| 前二包含率 | ≥ 97% |
| 无法解释差异 | 0（每个差异必须归类） |

差异分类：`保守跳过`（我们不做模拟器允许的危险动作）、`版本差异`（ID/机制变更）、`实现缺陷`（必须修）。

## 4. 游戏内 A/B（M2）

### 4.1 协议

- 同一角色、同一装备/天赋/增益，木桩（训练假人）180 秒；
- 每套方案 10 次，交替顺序（ABAB…）消除漂移；
- 记录：DPS、每技能施放次数、触发次数/消耗次数、引导次数/断引导次数、法力低于 5% 的时长、死亡次数；
- 日志用 `/combatlog` 导出，`tools/log_analyze.py` 解析。

### 4.2 统计

- 报告均值与 95% 置信区间（bootstrap 10k）；
- 配对比较（同一轮次内 A/B 差值），避免跨时间漂移；
- 显著性阈值：差值 95% CI 不跨 0；
- 样本不足时明确写"未达统计显著"，不下结论。

### 4.3 指标定义

| 指标 | 定义 |
| --- | --- |
| 触发利用率 | 窗口内消耗次数 / 触发次数 |
| 断引导率 | 被新施法打断的引导次数 / 引导总次数 |
| 空蓝时长比 | 法力 < 5% 的秒数 / 战斗秒数 |
| 溢出层数 | 触发达到上限后继续生成的次数（估算） |
| 决策延迟 | `decide()` 调用耗时 p50/p99 |

### 4.4 验收

M1：功能可用，无报错，三系循环正确（人工核对 10 分钟木桩）。
M2：G1 ≥ 95%（CI 下界 ≥ 92%）、触发利用率 ≥ 98%、断引导 ≤ 1%。

## 5. 性能测试

- 微基准：`bench/decide.lua`，100k 次，报告 p50/p99/最大；
- 帧测试：对比启用/禁用插件的帧时间（同一场景 60s，取中位数）；
- 内存：登录后、30 分钟战斗后各采样一次；
- 分配：热路径禁止 `table.concat`/临时表；代码审查 + `collectgarbage("count")` 前后差。

## 6. 回归与发布门槛

每次 PR 必须：

1. `tests/run.lua` 全绿；
2. profile schema 校验通过；
3. parity 报告无"无法解释差异"；
4. 性能不退化超过 10%；
5. changelog 有记录（改了什么、为什么、指标变化）。

发布前：

- 在至少 2 个客户端构建（当前 + 上一版）验证加载与派发；
- 与小六月最新版共存测试；
- 回滚包可用（上一版 zip）。

## 7. 遥测与隐私

- 默认**不联网**、不上传任何数据。
- trace 仅保存在本地 SavedVariables，`/mb export` 手动导出。
- 导出内容不含角色名/服务器（可配置脱敏）。
- 日志分析脚本在本地运行。

## 8. 数据 provenance

每个 fixture / profile 记录：

- 客户端构建号；
- 数据来源（WowSims commit、ForeverDB 日期、实测截图/日志）；
- 采集人/日期；
- 置信度（`verified` / `inferred` / `todo`）。

未验证的数据不得进入默认 profile，只能进 `experimental`。
