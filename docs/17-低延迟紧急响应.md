# 17 · 低延迟紧急响应（FAST LANE）

> 结论：DGX 负责“高质量决策与规则生产”，Windows 本地负责“时间敏感事件的即时判断”。
> 10 Hz 适合常规战斗决策，但**不应成为打断、驱散、保命的响应上限**。
> F0 仍然坚持 L2：FAST LANE 只负责“第一时间发现 + 预计算 + 提示”，玩家按 assist 才执行一次。

## 1. 双速架构

```
Windows 游戏机
  客户端 API + TitanForever + WGC 像素
        │
        ├── FAST LANE（30–60 Hz，本地）
        │     紧急检测 → 本地规则 → 预计算动作 → 提示/arm
        │     只处理：打断、驱散、紧急保命
        │
        └── NORMAL LANE（10 Hz → DGX）
              DPS、资源、爆发、AOE、2 GCD 预测
                       │
                 DGX 规则生产/优化
                       │ 编译后的紧急规则包（版本+哈希）
                       ▼
              Windows 本地解释器（无 eval、无热更新）
        │
   Action Arbiter：优先级 / 新鲜度 / 去重 / 急停 / 授权
        │
   ESP32 HID：一次 assist = 一个动作；不自动重试
```

| 通道 | 频率 | 位置 | 职责 |
| --- | --- | --- | --- |
| FAST LANE | 30–60 Hz | Windows | 打断、驱散、保命；检测与预计算 |
| NORMAL LANE | 10 Hz | DGX | APL、资源、AOE、预测、复盘 |
| 规则生产 | 离线/版本化 | DGX | 编译紧急规则包，签名/哈希 |
| 执行 | 事件驱动 | Windows → HID | 一次 assist 一次动作 |

## 2. 规则包（DGX → Windows）

```json
{
  "schema": 1,
  "version": "2026-11-20.1",
  "build": "1.60.1.70959",
  "hash": "sha256:...",
  "rules": [
    {
      "id": "interrupt.counterspell",
      "priority": 100,
      "when": {
        "target.casting.interruptible": true,
        "deadline.ok": true,
        "self.cds.2139.ready": true,
        "target.in_range": true
      },
      "action": {"type": "key", "key": "F"},
      "cooldown_ms": 8000,
      "dedupe": ["target.guid", "target.casting.castID"]
    },
    {
      "id": "decurse.remove_lesser_curse",
      "priority": 90,
      "when": {
        "friendly.cursed.count": {"gte": 1},
        "self.spell.475.ready": true,
        "friendly.target.valid": true
      },
      "action": {"type": "key", "key": "G"},
      "cooldown_ms": 0,
      "dedupe": ["friendly.guid", "debuff.id", "debuff.applied_at"]
    }
  ]
}
```

约束：

- Windows 只做**解释执行**，不 `eval`、不加载任意脚本；规则字段白名单。
- 版本/构建/哈希不匹配 → 拒绝加载，退回“只提示”。
- 规则包只能由 DGX 签发；本地不得自修改。
- 每条规则带 `cooldown_ms`、`dedupe`、`priority`、`deadline` 策略。

## 3. 授权边界（解决 docs/15 与 PROMPT-NEXT 的冲突）

| 模式 | 谁触发 | 是否发键 | 阶段 |
| --- | --- | --- | --- |
| L0 观测 | — | 否 | 默认 |
| L1 建议 | FAST LANE/DGX | 否 | 默认 |
| **L2 assist** | **玩家按键** | **一次** | F0 |
| L3 自动紧急 | 规则 | 是（未来） | 不在 F0 |

- **F0 不提供自动打断/自动驱散**。FAST LANE 可以 30–60 Hz 检测并立即提示，但不能越过 assist 键。
- 未来的 `EMERGENCY_AUTO` 是独立模式：单独开关、单独权限、单独测试门槛（F0-A/B/C 通过 + 实机时长 + 误触发=0），不得隐式启用。
- `docs/15 §5.1` 已同步改为“只提示，不自动执行”。

## 4. 动态截止时间（替代固定 `remain > 0.35`）

```
T_remain > T_state_age + T_input_p99 + T_server + T_safety
```

| 项 | 含义 | 初始值（待实测） |
| --- | --- | --- |
| `T_state_age` | now − 该字段 observed_at | 按字段，见 §5 |
| `T_input_p99` | assist 键 → HID → 游戏接收 | 20–50 ms |
| `T_server` | 服务器处理/网络 | 30–80 ms（实测后收紧） |
| `T_safety` | 安全余量 | 50 ms |

不满足 → `deadline.ok=false`：只显示“来不及”，不发键；不要用固定阈值硬赌。

## 5. 字段级新鲜度（替代统一 2 s）

| 字段 | max_age | 理由 |
| --- | --- | --- |
| `target.guid` | 200 ms | 目标切换必须立刻失效 |
| `target.casting.spellId/castID/remain` | 80 ms | 打断的核心 |
| `self.cds[2139]` | 150 ms | 反制是否可用 |
| `self.gcd` | 100 ms | 是否卡 GCD |
| `friendly[*].debuffs` | 200 ms | 驱散 |
| `hp` | 150 ms | 保命 |
| 普通 DPS 字段 | 2 s | 诊断/非紧急 |

超过 `max_age` → `valid=false`；FAST LANE 对该字段视为“未知”，不触发。

## 6. 友方单位与解诅咒

现有 CombatState 只有玩家/敌方/竞技场，**缺少 party1–4、raid1–40**。新增：

```json
"friendlyUnits": [
  {
    "guid": "0x...", "name": "队友", "class": "PRIEST", "role": "HEALER",
    "hp": 0.62, "distance": 12.4, "inRange": true, "validTarget": true,
    "debuffs": [
      {"id": 12345, "name": "诅咒", "type": "curse", "remain": 8.2,
       "priority": 80, "dispellable": true}
    ]
  }
]
```

- 只导出**有可驱散 debuff** 的友方，控制块 4574 B 预算内优先保留高优先级。
- `dispellable` 必须由当前客户端法术书/技能机制确认（法师：解除次级诅咒），不能只凭名称。
- 优先级：坦克 > 治疗 > DPS；同角色按 debuff 危险度 + 剩余时间排序。
- `validTarget` 必须为真；目标不明确时只提示“驱散 X”，不发键。
- 施法前再次校验 debuff 仍在、目标 GUID 未变；变了就取消。
- 不使用“自动选友方目标”；需要玩家预先选中或使用预建宏/键位。

## 7. Action Arbiter

| 步骤 | 规则 |
| --- | --- |
| 优先级 | 致命保命 > 打断 > 驱散 > DPS（可配置） |
| 新鲜度 | 任一关键字段 `valid=false` → 取消 |
| 去重 | `(规则, guid, castID/debuffId, applied_at)` 只执行一次 |
| 冷却 | 规则 `cooldown_ms` + 技能真实冷却双重校验 |
| 授权 | 无 assist 键 → 只提示 |
| 急停 | stop/闸门关闭 → 取消并松键 |
| 重试 | 不自动重试；失败记录后交给人 |

## 8. 指标（必须分开）

| 指标 | 定义 |
| --- | --- |
| `T_suggest` | 状态出现 → 提示显示 |
| `T_effect` | assist 按下 → 游戏内技能生效（GCD/光环/事件） |
| `T_confirm` | 生效 → 确认事件（`SPELL_INTERRUPT` 等） |
| 成功率 | confirmed / attempt |
| 误触发 | 不可打断/无 debuff/距离不够仍发键 |
| 重复 | 同一去重键多次发键 |

不要把这些合成一个“响应延迟”。

## 9. 验收实验

| 编号 | 场景 | 对照 | 成功标准 |
| --- | --- | --- | --- |
| **F0-A** | 快速反制 | DGX 10 Hz 普通路径 vs Windows FAST LANE 30–60 Hz | 检测→HID 的 p50/p95/p99；成功率；误触发 0 |
| **F0-B** | 多名友方同时中诅咒 | 无优先级 vs 优先级排序 | 正确识别、排序合理、**零错误驱散** |
| **F0-C** | Boss 读条 + 队友需要驱散 | 单通道 vs Arbiter | 仲裁可解释、不重复发键、状态过期自动取消 |

每个实验都要固定：构建号、装备/天赋、UI scale、HDR 状态、样本量、随机种子（如适用）。

## 10. 风险

- WGC 快速采样与 addon 10 Hz 的时序错位：以字段 `observed_at` 为准，不用“最新帧”冒充。
- 像素误判（施法条颜色/遮挡）：必须与 addon 交叉校验；冲突时 addon 优先。
- 规则包版本漂移：构建/哈希不匹配直接拒绝。
- 动作条映射变化：启动时校验键位，缺失则只提示。
- 自动紧急模式的行为特征：未来模式必须单独评估，不混入 F0。
