# 10 · 全职业扩展设计（M4）

> 目标：新增职业/专精**只写 profile**，不改 `core/`。本文定义需要抽象的状态维度与条件集。

## 1. 为什么现在就要设计

法师只用"法力 + 光环 + 冷却"，但战士用怒气、盗贼用能量/连击点、德鲁伊用形态、萨满用图腾、圣骑士用圣印、猎人用宠物与自动射击。如果状态模型一开始只写法力，M4 会推倒重来。

## 2. 状态抽象

### 2.1 资源

```lua
state.resources = {
  mana   = { cur, max, pct },
  rage   = { cur, max, pct },
  energy = { cur, max, pct },
  combo  = { cur, max },
  runes  = { {cd=...}, ... },   -- DK
  shards = { cur, max },        -- 术士
  holy   = { cur, max },        -- 圣骑士
}
```

规则字段：`resource = { type="rage", min=30 }`；`combo = { min=3 }`。

### 2.2 形态/姿态/圣印

```lua
state.form = "CAT" | "BEAR" | "MOONKIN" | nil
state.stance = "BATTLE" | "DEFENSIVE" | ...
state.seal = "COMMAND" | ...
```

规则：`form="CAT"`、`stance="BERSERKER"`、`sealMissing="COMMAND"`。

### 2.3 宠物/图腾/陷阱

```lua
state.pet = { exists, hpPct, mode }
state.totems = { fire=..., earth=..., water=..., air=... }
```

规则：`petMissing=true`、`totemMissing="fire"`。

### 2.4 近战/远程与位置

```lua
state.range = { melee=true, min=..., max=... }
state.positional = "BEHIND" | "FRONT" | nil
```

规则：`meleeRange=true`、`behind=true`。

### 2.5 目标集合

```lua
state.targets = { count, closeCount, boss, creatureType, execute }
```

规则：`aoe=3`、`aoeClose={n=3, range=10}`、`creatureType="UNDEAD"`。

## 3. 条件集扩展（向后兼容）

| 新字段 | 语义 | 首批使用者 |
| --- | --- | --- |
| `resource` | 某资源 ≥/≤ N | 战士/盗贼/德鲁伊 |
| `combo` | 连击点 ≥/≤ N | 盗贼/德鲁伊 |
| `form` / `formMissing` | 形态 | 德鲁伊 |
| `stance` | 姿态 | 战士 |
| `seal` / `sealMissing` | 圣印 | 圣骑士 |
| `totemMissing` | 图腾缺失 | 萨满 |
| `petMissing` | 宠物缺失 | 猎人/术士 |
| `meleeRange` | 近战距离 | 战士/盗贼 |
| `behind` | 背后 | 盗贼/德鲁伊 |
| `creatureType` | 目标类型 | 圣骑士/猎人 |
| `swingTimer` | 平砍计时 | 战士 |
| `threat` | 仇恨 | 坦克 |

所有新字段必须是**纯查询**，不允许触发动作。

## 4. Profile 模板

```lua
return {
  schema = 1,
  class = "WARRIOR",
  spec = "ARMS",
  game_build = "1.60.1.70959",
  meta = { source = {...}, confidence = "draft" },
  resources = { "rage" },
  rules = {
    { id="arms.charge", spell="冲锋", target=true, cd=true, resource={type="rage", max=5} },
    { id="arms.rend", spell="撕裂", target=true, debuffMissing={id=..., unit="target"} },
    { id="arms.ms", spell="致死打击", target=true, cd=true, resource={type="rage", min=30} },
    { id="arms.slam", spell="猛击", target=true, resource={type="rage", min=15}, filler=true },
  },
}
```

## 5. 分阶段

| 阶段 | 职业 | 理由 |
| --- | --- | --- |
| M4.1 | 战士（武器/狂暴） | 怒气模型简单，近战距离 |
| M4.2 | 盗贼（战斗/刺杀） | 连击点 + 背后 |
| M4.3 | 猎人（射击/兽王） | 宠物 + 自动射击 |
| M4.4 | 德鲁伊（猫/熊） | 形态切换 |
| M4.5 | 圣骑士/萨满/牧师/术士 | 圣印/图腾/治疗 |

每个专精的准入条件与法师相同：golden、parity（有模拟器则对比）、木桩 A/B、trace。

## 6. 维护成本控制

- 引擎条件集只增不改语义；新增字段必须写 ADR。
- 每个职业一个 owner（人或 AI），profile 变更需附数据。
- 每季度用最新客户端构建回归一次；不活跃的 profile 标记 `stale`，不删。
- 公共逻辑（打断、保命、AOE 判定）抽到 `profiles/common/`，避免复制。

## 7. 不做什么

- 不做治疗专精的智能奶（只做 DPS 填充 + 紧急保命）。
- 不做坦克仇恨循环（风险高，收益低）。
- 不做 PvP 决策（控制链、假动作无法用静态 APL 表达）。
