# 06 · 路线图

> 每个里程碑都有**可验收的产物**与**退出条件**；不达标不进入下一阶段。

## M0 · 设计（当前）

**产物**

- 本仓库全部文档：总纲、竞品研究、架构、APL 规范、派发通道、测试方案、数据字典、评审指南；
- 小六月 1.3.4 逆向分析（架构级，不含代码）；
- 三系 profile 草案（JSON，可评审）；
- 架构决策记录（ADR 0001–0005）。

**退出条件**

- 外部 AI 评审完成，P0 问题清零；
- 数据字典中 `TODO(probe)` 项有明确的验证脚本/步骤；
- 仓库可被第三人按文档复现理解。

## M1 · Companion MVP（法师三系）

**范围**

- 作为小六月的伴生插件加载（`Dependencies: LiuyueForever`），不修改其文件；
- 接管 `EffectiveChain` / `PickIndex`（仅法师）；
- 实现 Observe（光环/冷却/施法/姓名板）、Decide（优先级 + guard）、Act（复用其安全信道）、UI（队列 + 触发条 + `/mb`）；
- 三系 profile 上线：冰、火、奥；
- `/mb test` 输出完整 trace。

**不包含**：多步预测、独立 UI、全职业、自动更新。

**验收**

- 三系木桩 10 分钟无报错；
- 关键场景 fixture 全绿（寒冰指冰枪、3 层炎爆、飞弹连射、奥冲 4 层、空蓝唤醒、移动火冲、打断）；
- 决策耗时 p99 ≤ 0.3 ms；
- 与小六月 1.3.4 共存，无 taint 报错。

**风险**：上游 API 变动；宽度信道在 1.60.1 的实际表现；光环 ID 与来源不一致。
**回滚**：`/mb off` 立即恢复原版；卸载插件不影响小六月。

## M2 · 数据校准

**范围**

- `tools/apl_import` 完成 WowSims APL → IR；
- parity harness 跑通，输出一致率与差异分类；
- 游戏内 A/B：木桩 180s ×10，解析日志；
- 根据数据修正阈值（唤醒、奥冲、AOE、灼烧维持）；
- 引入可选的 2 步 lookahead（默认关闭）。

**验收**

- 首选一致率 ≥ 90%，前二包含率 ≥ 97%；
- 无法解释差异 = 0；
- 木桩 DPS / 模拟 ≥ 95%（CI 下界 ≥ 92%）；
- 触发利用率 ≥ 98%，断引导 ≤ 1%。

**风险**：模拟器与实服差异；样本量不足；装备/天赋不匹配。
**回滚**：profile 版本化，可一键切回 M1 基线。

## M3 · Standalone 核心

**范围**

- 自带 Act（安全信道）与 UI，不再依赖小六月；
- 适配层抽象：`adapter/liuyue.lua` 与 `adapter/standalone.lua` 二选一；
- 兼容导入小六月 APL 字符串（LYF1 子集）；
- 安装包自包含（无外部二进制）。

**验收**

- 在 2 个客户端构建上稳定运行；
- 卸载小六月后功能完整；
- 安全信道失效时有明确降级与提示；
- 性能与 M2 持平。

**风险**：安全模板/宽度通道在新构建失效；UI 工作量。
**回滚**：保留 Companion 模式开关。

## M4 · 全职业

**范围**

- 抽象职业差异：资源（法力/怒气/能量/连击点/符文）、姿态/形态、图腾、宠物、连击窗口；
- 通用条件集扩展（`resource`、`combo`、`form`、`totem`、`pet`）；
- 每职业先做 1 个专精，按同一测试标准上线；
- 社区 profile 贡献流程（schema 校验 + parity + 实机验证）。

**验收**

- 新增职业不改 `core/`；
- 每个专精有 golden、parity、木桩报告；
- 文档包含"如何新增一个专精"的 30 分钟教程。

**风险**：范围爆炸；职业机制差异大；维护成本。
**策略**：按使用率排序，法师 → 战士/盗贼/猎人 → 其余。

## 版本与分支

- `main`：始终可安装；
- `profile/<spec>`：规则实验分支，合并前必须有 A/B 数据；
- tag：`v0.x.y`，与客户端构建号一起记录在 release notes。
