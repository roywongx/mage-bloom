# 00 · 项目总纲

## 1. 背景

《魔兽世界：无限》（下称"无限服"）使用独立客户端分支 `_forever_`，当前构建 `1.60.1.70959`，Interface `16001`。法师在经典框架上叠加了五个自定义机制：

- **奥术冲击**：每次施放叠加"奥术冲击"自身增益（智力转化法伤），下一发蓝耗翻倍，最多 4 层，持续 18 秒；
- **飞弹连射**：触发后强化下一次奥术飞弹（更快、免蓝）；
- **热力迸发**：火焰暴击叠加，3 层时炎爆术可瞬发；
- **寒冰指**：使目标视为冻结，冰枪术对冻结目标三倍伤害；
- **霜火之箭**：40 级学习的冰火混合填充。

这些机制让"照搬经典 APL"必然次优：经典法师没有热力迸发层数，也没有"奥冲层数 + 飞弹连射"的取舍。

## 2. 问题定义（证据）

对小六月 1.3.4 的逆向分析（[08](08-小六月原版分析.md)）显示：

| 问题 | 证据 |
| --- | --- |
| 法师 APL 过薄 | `Core/APL.lua` 中 MAGE 三系各 3–4 条，无触发、无 AOE、无法力判断 |
| 条件引擎缺失 | APL 字符串字段表无 `buff`（存在+层数）、无 `castTime`、无 `channeling` 细分 |
| 触发不可用 | 引擎不识别 `400625/400589/400573/400669` 等无限服触发 |
| 决策不可观测 | 仅内部日志，无稳定 trace、无回放 |
| 学习成本 | 字符串 XOR(123) 混淆，社区无法审阅策略 |

结论：不是"再加几条规则"，而是需要一个**有状态模型、有条件代数、可测试**的决策核心。

## 3. 目标（可量化）

| ID | 目标 | 指标 | 验收 |
| --- | --- | --- | --- |
| G1 | 单目标不弱于官方模拟器 | 木桩 180s DPS / WowSims 同装备模拟 | ≥ 95%（n≥10，95% CI 下界 ≥ 92%） |
| G2 | 触发零浪费 | 触发窗口内被消耗比例 | ≥ 98% |
| G3 | 引导零误断 | 引导被新推荐打断的比例 | ≤ 1% |
| G4 | 决策开销可忽略 | `decide()` 单次耗时 | p99 ≤ 0.3 ms，10 Hz 轮询 |
| G5 | 决策可复现 | 同一 fixture 输出一致 | 100% |
| G6 | 可扩展 | 新增专精不改引擎代码 | 仅新增 profile 即可通过测试 |
| G7 | 兼容小六月生态 | 与小六月 1.3.x 共存 | 不修改其文件、不产生 taint |

## 4. 非目标

- **不**做自动战斗/自动移动/自动选目标/自动打断以外的自动化；一次用户按键对应一次动作。
- **不**做封包、注入、内存读取、客户端修改。
- **不**做完整 DPS 模拟器（模拟器用 WowSims，我们只做在线决策）。
- **不**依赖 WeakAuras；WA 字符串只作为可选的策略导入格式。
- **不**追求"全职业同时上线"；先法师三系打穿，再抽象到全职业。

## 5. 设计原则

### P1 三层分离
```
Observe（只读快照） → Decide（纯函数） → Act（安全派发）
```
- Observe 只读公开 API，不缓存过期状态；
- Decide 不调用任何写 API，输入 `State + Profile + Config`，输出 `Decision + Trace`；
- Act 只在玩家点击瞬间把"已提交的决策"翻译成安全属性。

### P2 数字有出处
每个技能 ID、光环 ID、优先级，都在 [09 数据字典](09-法师数据字典.md) 标注来源（WowSims commit / ForeverDB build / 客户端实测）。待验证项显式标 `TODO(probe)`。

### P3 先测量再调参
规则改动必须绑定一个指标与一次对照实验；变更记录写入 `CHANGELOG.md` 与 profile 的 `changelog` 字段。

### P4 失败保守
以下情况一律返回"无推荐"：玩家死亡/坐骑/传送、目标不存在或友方、技能未学会、法力不足、超出距离、正在引导且候选非瞬发、状态读取异常。

### P5 最小惊讶
默认配置即安全配置：不自动开爆发（可开关）、不自动吃宝石、不在移动时推荐读条。所有"聪明"行为可关闭。

## 6. 范围

| 阶段 | 范围 |
| --- | --- |
| M1 | 法师：冰 / 火 / 奥三系，单目标 + AOE + 移动 + 打断 + 保命 |
| M2 | 数据校准：与 WowSims APL 决策一致率、木桩 A/B |
| M3 | 独立核心：不再依赖小六月的引擎，只保留可选兼容层 |
| M4 | 全职业：抽象资源/连击点/姿态/图腾等状态，新增 profile |

## 7. 约束

- **客户端**：`_forever_` 1.60.1.x，Interface 16001；API 随构建变化，必须有 shim 层。
- **战斗锁定**：战斗中不能改安全帧属性；动态施法必须走"点击瞬间在受限环境改属性"的通道。
- **性能**：10 Hz 轮询，单帧总开销 < 0.5 ms；热路径不分配表。
- **分发**：新手盒子 / 手动安装；不引入外部二进制。
- **合规**：只响应按键；不读取未公开信息；不绕过客户端保护。

## 8. 术语

| 术语 | 含义 |
| --- | --- |
| State | 某一时刻的只读游戏状态快照 |
| Profile | 某专精的规则集合（数据） |
| Rule | 一条"条件 + 技能" |
| Guard | 规则的前置条件 |
| Trace | 决策轨迹：每条规则的通过/跳过原因 |
| Commit | 把决策索引写入安全信道，等待点击 |
| Parity | 与 WowSims APL 在同一状态下的决策一致率 |

## 9. 成功定义

M1 完成时，一个 60 级法师玩家可以：
1. 把插件放进 AddOns，登录即用，无需配置；
2. 按一个键，按三系正确循环输出，触发不浪费、引导不断；
3. 打开 `/mb test`，看到"为什么现在推荐这个技能"；
4. 开发者拿到一份可复现的 trace，能在离线测试里重现同一次决策。
