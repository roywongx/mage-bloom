# 14 · 人类主导的智能战斗助手

> 产品定义：玩家仍然按键、走位、选目标；系统只做**感知、判断、提示**，可选“一键 assist”。
> 不做自动移动、自动选目标、全自动循环；不依赖服务器 API。

## 1. 协助等级

| 等级 | 行为 | 是否采用 |
| --- | --- | --- |
| L0 观测 | 记录战斗、复盘、指标 | ✓ 默认 |
| L1 建议 | 屏幕/副屏/语音提示“下一手、打断、保命” | ✓ 默认 |
| L2 一键 assist | 玩家按专用键一次，系统代按一个技能键 | ✓ 可选 |
| L3 全自动 | 不需要玩家输入 | ✗ 非目标 |

L2 的边界：**一次玩家按键 = 最多一次游戏动作**；没有玩家按键，系统不施法。

## 2. 数据最大化：先把“读”做到极致

### 2.1 现有来源

| 来源 | 能读到什么 | 频率 | 用法 |
| --- | --- | --- | --- |
| 小六月 `AuraState` / `SpellDuration` | 光环存在、层数、剩余、DoT 保护 | 10 Hz | 触发/维持 |
| 小六月 `SpellBook` / `SpellIdCandidates` | 技能 ID/rank/学习等级 | 载入 | 解析当前 rank |
| 小六月 `Talents` / `TalentData` | 专精、天赋预设 | 事件 | 切 profile |
| 小六月 `Ledger` / `TTD` / `FailWatch` | 资源账本、预计死亡、失败冷却 | 10 Hz | 资源/保命 |
| 小六月 `APL` / `RotationTips` | 规则与经验 | 载入 | 基线策略 |
| `TitanForever` 控制块 | 位姿、target GUID、casting、flags、窗口 | 5–10 Hz | 战斗态底座 |
| `SpellActivationOverlay` | 触发 ID（寒冰指/热力迸发/飞弹连射） | 事件 | 触发校验 |
| `DungeonsForeverSpell` | 全量技能与 rank | 载入 | 补全 ID 表 |
| 客户端 API | `C_UnitAuras`、`C_Spell`、姓名板、CLEU | 10–20 Hz | 原始事实 |
| 像素探针 | 施法条、生命条、buff 图标、位置 | 15–30 Hz | 补 addon 读不到/延迟大的部分 |

```json
    "gcd": 0.42, "cast": {"id": 8407, "remain": 1.2, "channel": false},

    "cds": {"1240047": 5.2, "2139": 0},
    "moving": false, "inCombat": true
  },
  "targets": [
    {"guid": "0x...", "name": "对手", "class": "MAGE", "specGuess": "FROST",
     "hp": 0.62, "distance": 18.4,
     "casting": {"id": 12345, "remain": 0.8, "interruptible": true},
     "buffs": [{"id": 44544, "n": 1, "rem": 6.0}],
     "debuffs": [{"id": 22959, "n": 5, "rem": 7.1}],
     "dr": {"root": 0.5, "stun": 1.0}}
  ],
  "arena": [{"index": 1, "guid": "...", "hp": 0.7, "casting": null}],
  "pixels": {"targetCastPct": 0.42, "targetHpPct": 0.61, "nameplateCount": 3}

```

- `targets` 至少覆盖 target / focus / arena1-3 / 姓名板敌人。
- `pixels` 只放**本地解码后的数值**，不放图像。
- 所有 `id` 优先 spellId；名称为辅。

## 3. 像素探针（结构化，不做 OCR）

### 3.1 原则

- 只采样**固定矩形内的固定像素点**，输出数值（百分比/存在位/颜色分类），不把截图送模型。
- 采样前用 finder/校准块校验 UI 缩放与颜色管理；失败即 `unknown`。
- 与 addon 数据交叉校验：两者冲突时，addon 优先，像素标记 `disagree`。

### 3.2 采样点

| 区域 | 采样 | 输出 |
| --- | --- | --- |
| 玩家施法条 | 进度条左/右端 + 中心色 | `castPct`、`channel` |
| 目标施法条 | 同上 + 图标颜色 | `targetCastPct`、`interruptible` 猜测 |
| 目标/焦点血条 | 左端、右端、背景 | `hpPct` |
| 姓名板 | 每块血条宽度 + 职业色 | `nameplates[{hp, class, x}]` |
| 竞技场框体 | 1–3 号血条/施法条 | `arena[i].hp/cast` |
| buff 图标区 | 固定格子的存在/边框色 | `buffPresent`（仅补充） |

### 3.3 频率与延迟

- 本地采集 15–30 Hz；解码 <5 ms；只把数值推给 DGX。
- 像素路径的延迟目标 ≤50 ms，用于**打断/保命**这类 deadline 紧的判断。

## 4. DGX 决策

### 4.1 PvE

- 纯 APL + 2 GCD 预测（默认关闭，实验开启）。
- 触发、层数、资源、AOE、移动、打断、保命。
- 输出：`next 3 actions + reason + confidence`。

### 4.2 PvP

| 模块 | 规则 |
| --- | --- |
| 目标价值 | 治疗 > 法系 > 近战；残血/无 trinket 加权 |
| 打断 | 只打断“危险且可打断”的读条；按剩余时间排序；避免与队友重复 |
| 控制 | DR 递减跟踪；控制链不重叠；优先在对方无 trinket 时交 |
| 爆发 | 对方 defensives 冷却/己方 proc/饰品可用时提示 |
| 生存 | 血量、护盾、位移、冰箱；提前 1 GCD 提示 |
| 走位 | 只提示“远离/卡视野/进柱”，不自动移动 |

### 4.3 规则 vs 模型

- 实时：确定性规则（可解释、可回放）。
- 模型：离线复盘、对手习惯建模、赛前建议；不进入 10 Hz 热路径。
- 任何模型输出必须带 `model_version` 与 `confidence`，低置信回退规则。

## 5. 建议怎么回到人眼前（真正的难点）

addon 不能开 socket、不能读文件；DGX 不能直接往游戏里写 UI。可选路径：

| 方案 | 延迟 | 侵入性 | 结论 |
| --- | --- | --- | --- |
| 副屏/平板 Web（DGX 页面） | 100–200 ms | 零 | **首选** |
| 游戏机上的透明置顶 overlay | 50–150 ms | 中（需窗口化） | 二期 |
| 语音 TTS（打断/保命） | 200–400 ms | 零 | 辅助 |
| 游戏内 addon 显示 | 0 ms | 需 DGX→addon 通道 | 不可行（无网络） |
| 聊天/宏注入建议 | 300 ms+ | 高（可见） | 不采用 |

**首选组合**：DGX 提供 `/assist` Web（下一手 3 个技能、敌方冷却、打断提示、DR），玩家用副屏/平板看；关键事件加 TTS。

## 6. 执行（L2 assist）

- 玩家按住/按一次“assist 键” → DGX 发出**一个**已排好的技能键 → esp32d HID。
- 没有 assist 键按下，DGX 不发任何游戏输入。
- 租约、闸门、急停全部复用 `wow-esp32d`。
- 验收：下一次状态帧出现 GCD/光环变化；300 ms 未确认则记失败，不重按。

## 7. 延迟预算

| 段 | 预算 |
| --- | --- |
| addon 色块 → DGX | 100–200 ms |
| 像素探针 → DGX | ≤50 ms |
| 决策 | ≤5 ms（PvP 规则）/ ≤10 ms（2 GCD） |
| HID → 游戏 | 20–50 ms |
| 状态回传确认 | 100–200 ms |
| **建议显示** | 150–250 ms |
| **assist 执行** | 150–300 ms |

PvP 打断必须用像素/本地快路径，不能只等 addon 帧。

## 8. 人类化与检测

- 建议显示不产生输入；L2 只在玩家按键时发一个动作。
- 不对“完美反应”做自动化；TTS/提示允许人迟 100–300 ms。
- assist 键的连按间隔、按下时长、APM 仍按 `docs/12` 的人类化参数。
- 不使用自动选目标/自动移动/自动打断循环。

## 9. 路线图（相对 v1 的增量）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| A1 | CombatState schema + addon 导出（含光环/GCD/冷却/arena） | 10 Hz 稳定，字段齐全 |
| A2 | DGX 接收 + 规则引擎（PvE APL） | 与木桩/副本一致率 |
| A3 | `/assist` Web + 副屏 | 延迟 ≤250 ms，可读 |
| A4 | 像素探针（施法条/血条/竞技场） | 与 addon 一致率 ≥99%，延迟 ≤50 ms |
| A5 | PvP 规则（打断/DR/爆发/生存） | 实战回放评估 |
| A6 | L2 assist（可选） | 一次按键一次动作，零误触 |

## 10. 与 v2 的关系

- 保留：DGX 决策、APL/预测、回放测试、数据化。
- 替换：服务器授权执行 → **客户端状态 + 人类主导 + HID assist**。
- 放弃：自动移动/自动选目标/全自动循环/服务器 API。
